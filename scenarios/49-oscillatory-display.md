# 49. Oscillatory Display

- Status: Speculative
- Interface point: Neural timing and attention
- Carrier: Rhythmic sensory, prosthetic, or neural cue
- Transducer: Output channel depends on implementation
- Encoding style: Frequency, phase, synchrony, or rhythm
- Addressing method: Time-based grouping
- Expected percept: Rhythmically organized cue interpretation
- Related modules: [Signal Encoding](../modules/02-signal-encoding.md), [Visual Pathway](../modules/07-visual-pathway.md)

## Summary

An oscillatory display uses rhythm as part of the code. Instead of representing
only where something is, it also represents when and how strongly it should bind
with other cues.

## Chain Map

```text
feature
-> rhythm or phase code
-> output cue
-> temporal grouping
-> perceived relation
```

## Possible Uses

- Group related object parts with a shared rhythm.
- Use faster pulses for urgency.
- Use phase differences for direction or depth.
- Encode confidence through rhythm stability.
- Separate multiple objects by different temporal patterns.

## Expansion Ideas

- Musical visual substitution.
- Tactile rhythm maps.
- Phosphene pulse grammar.
- Scene skeletons with rhythmic object grouping.
- Attention cues that pulse only when the scene changes.

## Research Questions

- Which rhythms are easiest to distinguish?
- Can timing reduce visual or tactile clutter?
- Can rhythm create object grouping from sparse cues?
- When does rhythmic coding become annoying or fatiguing?
